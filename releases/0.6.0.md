# Zoer Connect 0.6.0 (development)

Includes the unreleased 0.5.4 request-fence fix (see `0.5.4.md`; destination setup must
be confirmed again before the next import).

## Publication identity: what visitors actually receive

A completed transfer did not prove that visitors saw it. On 2026-10-16 an Apex
publication completed, but the plain homepage was still served from the hosting CDN
(`x-hcdn-cache-status: HIT`) with the previous theme and copy, while a cache-busting
query URL showed the new content.

- Each completed import (push, Find & Replace) and each completed rollback commits a new
  opaque, random publication identifier (`zoer_connect_publication`), bound to its import.
  It is not the import ID and carries no secret.
- Normally rendered public HTML carries it in `<meta name="zoer-publication">` and the
  `X-Zoer-Publication` header. Singular pages also carry `<meta name="zoer-revision">`, a
  short hash of the post ID, modification time and content, so old page content behind a
  current theme (stale object or fragment cache) is detectable. Password-protected posts
  expose no revision. Admin, REST, AJAX and feed responses carry neither.
- Authenticated `GET /publication` (Push or Pull permission) returns the expected identity,
  the home URL and the front page plus up to eight recently modified published pages and
  posts with their revisions, read from the database rather than the object cache.
- `status.capabilities.publicationIdentity` and `cacheReceipts` advertise both features.
  Older connectors are reported by Zoer as "Not verifiable", never as current.

## Cache purges leave per-layer receipts

- Queued purges (import option `purgeCaches`) record `state: queued` until the next
  normal page load runs them; then each cache plugin is listed as `requested` (its hook
  gives no confirmation), `not-detected` or `failed`, and the object cache as `flushed`,
  `failed` or `unavailable`.
- Authenticated `POST /cache/purge` (Push permission) runs the same purges now and returns
  the receipt. Hosting and CDN caches are outside WordPress and need the provider's purge.
- The publication and receipt options are destination runtime state: they are preserved
  across imports and excluded from the destination-change safeguard, so a public request
  writing a receipt during a later import's staging cannot cancel that import.

## Admin page

Tools → Zoer Connect is reorganised into a status header (Pull, Push, Imports, Private
storage, each with one fix link), Connection / Activity / Settings tabs, at most three setup
steps while setup is incomplete, and one sentence per control with explanations under
"Learn more". Form fields, actions, nonces and option names are unchanged; Reset key,
Revoke key and Delete profile now ask for a browser confirmation.

## Tests

`tests/publication-identity.php`, `tests/cache-purge.php` (per-layer receipts),
`tests/admin-page.php`; `tests/prefix-roles.php` ignores the publication marker when
comparing options after a rollback, like the other runtime markers.
