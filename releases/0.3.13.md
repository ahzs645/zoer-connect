# Zoer Connect 0.3.13 qualification

- Change: preserve the destination `blog_public` search-visibility option during database replacement.
- Change: queue a one-time soft permalink-rule refresh after a completed database or plugin/theme Push or rollback. It runs on the next normal WordPress request after the request fence is released and does not rewrite `.htaccess`. The generated rule option and the pending marker remain outside rollback content fingerprints; authored permalink and search settings remain protected.
- `make test` passed in PHP 8.1, 8.2 and 8.3 with ZIP support as an unprivileged user, including destination-option preservation, retry, rollback and updater checks.
- `python3 tests/build_test.py` passed deterministic ZIP and layout checks.
- Installed the candidate ZIP in a disposable WordPress 7.1.2 / MariaDB 11.4 installation. `wp eval-file tests/integration/rewrite-visibility.php` verified destination search visibility survives a source value of zero, the queued permalink refresh completes, a later authored visibility edit blocks rollback, and rollback restores the original options table. The disposable installation was not the PGAIR site.
- The release ZIP SHA-256 is recorded in `0.3.13.json` and in the public release manifest. No connection keys or private source files are packaged.
- Published to `ahzs645/zoer-connect-releases`; the existing PGAIR 0.3.12 installation discovered 0.3.13 in the WordPress dashboard and updated successfully. Zoer then verified the connected plugin as 0.3.13. Push/Pull permissions remained enabled, the destination indexing preference remained enabled, and the homepage and Wood Smoke course returned HTTP 200. No production content Push was run for this qualification.
