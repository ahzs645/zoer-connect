# Zoer Connect 0.8.0 (development)

## Release candidates, if a site asks for them

- Tools → Zoer Connect → Settings → **Updates** has *Also offer release candidates*. Only
  administrators who can update plugins see and change it (nonce-checked `admin-post` form); it is
  off by default.
- With it on, the updater lists this repository's releases through the GitHub API, takes the
  newest stable release or `-rc.N` release candidate by version, and requires that release's own
  `update.json` to confirm the version and SHA-256. Downloads are verified exactly as for stable
  releases: only this repository's release ZIPs, each checked against its versioned manifest.
  Alpha and beta prereleases are never offered. With it off nothing changes: sites read
  `releases/latest/download/update.json`, which GitHub resolves to stable releases only.
- Saving the setting clears WordPress's cached update check, so the next check uses the new
  channel. Updates are never automatic (`autoupdate` stays false).

## Release candidate builds

- A prerelease tag `vX.Y.Z-rc.N` now builds a ZIP whose plugin header says `Version: X.Y.Z-rc.N`
  (the source stays `X.Y.Z`), so WordPress orders rc.1 < rc.2 < X.Y.Z, and publishes an
  `update.json` with that version next to it. The ZIP keeps the name `zoer-connect-X.Y.Z.zip`.
  Prereleases remain unqualified and are not marked latest.
