# Zoer Connect 0.9.0

0.9.0 includes the unreleased 0.8.1 storage and retention changes ([notes](0.8.1.md)) and the
migration fixes below, from a review against WP Migrate DB Pro 2.7.7. Every new behaviour is
compatible with existing Zoer clients; the new `/status` fields and the `languages` export option
are additive.

## Transfer storage and backup retention (from 0.8.1)

- Activity → Transfers can measure retained storage on demand. Ordinary page loads do not scan
  the filesystem.
- Administrators can opt into daily cleanup of finished imports older than 1–365 days (default
  30). The newest retained successful import is always protected; the setting is off by default.

## Migration fixes

- One snapshot format: the paged source-maintenance export now writes the ordinary
  `-- Zoer Connect database snapshot` header, so its SQL imports through Push and local
  copies. The importer also accepts the old `source-maintenance` header from 0.8.0 sources.
- Rows up to 16 MiB stage and verify (was 4 MiB), matching the 16 MiB export statement. A
  large row that the destination's `max_allowed_packet` cannot carry is refused with that
  reason. `/status` `transferLimits` adds `maxFiles` (20,000), `maxRecordBytes` and `maxRowBytes`.
- Reset secret key is refused while an unfinished import was created with the current key;
  Revoke key is unchanged. Transfers offers "Continue with the current key" for an unfinished
  import of an earlier key (administrator, nonce, HTTPS); the journal and fence are unchanged.
- Another WordPress installation's tables (`wp_shop_*` beside `wp_`) are left out of exports,
  refused when explicitly selected, reported by diagnostics (`otherInstallation`,
  `other_installations`) and refused by imports in every mode, not only with `createTables`.
- Find & replace: JSON objects and arrays are rewritten per decoded string and stay valid;
  binary, BLOB, BIT and spatial columns are skipped; text that only begins like serialized data
  is replaced as text (malformed serialized data is still refused).
- A destination with WordPress in a folder beneath its site address (siteurl
  `https://example.org/wp`) is accepted for clients that send import options. The job binds that
  siteurl; source `wp-content`, `wp-includes` and `wp-admin` URLs map into the folder.
- Export profiles accept `languages: true` (wp-content/languages); `capabilities.languages`.
  Translations are exported for Pull and local copies; Push still imports only themes, plugins
  and media.
- Verified by the PHP unit suites on macOS (the Linux `/proc` fixtures excepted). Not yet
  exercised against live hosting or the DDEV runtime.

## Upgrading

- Sites update from wp-admin when an administrator chooses; updates are never automatic. Do not
  update the connector during an active transfer.
- Exports no longer include another installation's tables that share the database (for example
  `wp_shop_*` beside `wp_`). Select them on that installation's own connection instead.
- A development build reporting 0.8.1 was installed on overtheedge.unbc.ca; it predates the
  migration fixes and is superseded by this release.

## Verified (2026-10-19)

- PHP unit suites (`make test` commands) on macOS PHP 8.5: all pass except the two Linux `/proc`
  fixtures (`import-admin.php`, `request-drain.php`), which cannot run on macOS, as before. The
  GitHub Actions PHP 8.1–8.3 Linux matrix runs the full suite for this commit and tag.
- New regressions, each confirmed to fail on 0.8.0 code where applicable: a completed
  source-maintenance export parses through the snapshot importer; another installation's tables
  are excluded/refused without `createTables`; JSON values stay valid and BLOB columns are
  byte-identical after replacement; key reset is refused and the adopt handler checks permission,
  nonce and HTTPS; a subdirectory destination imports and finishes; 16 MiB rows and the
  `max_allowed_packet` refusal; `languages` export profiles bind identically when absent.
- Package tests (`make test-package`) and the reproducible build.
- Not verified: live hosting, the DDEV runtime and the native updater for this version.

## Release status: owner-approved without integration qualification

Published at the owner's direction on 2026-10-19, like 0.5.3, 0.7.0 and 0.8.0, **without** live
hosting, DDEV or updater qualification. The receipt pins the runtime files and the ZIP.
