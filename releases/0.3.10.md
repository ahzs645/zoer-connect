# Zoer Connect 0.3.10 qualification

Reference inspected: user-supplied WP Migrate Pro 2.7.11, `class/Common/Migration/Flush.php` (object cache flush and rewrite regeneration), chunked transfer paths already described in the operating guide. No blanket early-cache-drop-in rejection was found in the inspected source. Implementation is independent; no third-party code copied.

Shared-hosting setup now explicitly permits regular advanced-cache.php/object-cache.php files; its exact generated MU bootstrap binds that mode into the private readiness identity. Strict worker mode still rejects both. db.php, sunrise.php, maintenance.php, symlinks and nonstandard content paths remain rejected. Known original MU bootstraps may switch mode atomically through authorized setup only while no import is active. Unknown bootstrap contents are never overwritten.

Recovery reads the key and destination URL from the database, and current owner capabilities from usermeta, rather than persistent option caches. Before reopening imports that affect DB/themes/plugins, the importer flushes the WordPress object cache inside the exclusive fence. Failure retains protection; replay retries invalidation. Page/CDN cache purges remain a separate host/plugin operation. No rewrite regeneration for the HTML-only transfer.

Validation: all existing Makefile PHP tests passed under an isolated network-disabled DDEV image as uid 1000. A root-run storage-test failure was environmental (root can write chmod-protected directories); rerunning as an unprivileged user passed. New shared-cache bootstrap/auth tests passed. New cache-flush failure and finish retry assertions passed in transfer-import.php. PHP syntax checks and deterministic ZIP layout checks passed.

Real disposable zoer-connect-transfer-peer only: installed candidate runtime, explicitly enabled shared mode, added two inert cache drop-in fixtures, and transferred a 528000-byte HTML file over native HTTPS import routes with duplicate chunk retries. Verified on-disk/upstream HTTP SHA, interrupted rollback, a second completed import, finish and post-finish rollback. Admin AJAX upstream returned 503 during the fence; anonymous import recovery was refused. The managed DDEV vanity proxy cannot resolve ordinary pages during the pause and reports 502; native upstream verification was used. wp-cron.php may close its HTTP response before WordPress bootstrap, so its HTTP status is not proof of fence behavior. Fresh-process cron bootstrap refusal is covered by unit tests.

Peer original plugin, MU bootstrap, readiness receipt, key and cache fixtures were restored. Peer home/siteurl, complete user rows and post rows compared equal before/after. Both cache fixtures are inert; this is not Redis persistence or all third-party page-cache-provider qualification. Existing DB publication tests remain regression coverage, not a newly completed large DB migration under Redis.

0.3.9 installed successfully on Aram, but the live host disables PHP link(), discovered during explicit setup. 0.3.10 serializes bootstrap installation with the private control lock and uses a fully flushed atomic rename fallback when link() is unavailable. Shared and strict fence tests and admin setup tests passed with PHP disable_functions=link. Existing artifact-reuse clients fall back to fresh upload offsets; capability reporting disables reuse when link() is unavailable. File-import, finish retry and cache-auth regression tests passed after this change. Deterministic packaging passed. No customer content import occurred before these checks.
