# Zoer Connect 0.5.2

WordPress update discovery and ZIP downloads now use the public
`ahzs645/zoer-connect` repository's GitHub Releases directly. Stable releases
include an `update.json` asset containing the exact qualified version and ZIP
SHA-256. The updater reads `releases/latest/download/update.json`, then verifies
the ZIP against the immutable versioned `releases/download/vVERSION/update.json`.
GitHub's asset redirects are supported; metadata remains bounded to 4 KiB.
Malformed versions, missing metadata, version mismatches and altered ZIPs fail
closed. Automatic updates remain off unless the administrator enables them.

0.5.2 is also the final migration bridge published to `zoer-connect-releases`.
Sites running older connectors discover and install it through their existing
WordPress update workflow, retaining keys, permissions, private storage and
transfer journals. Once installed, subsequent update checks use `zoer-connect`.
The old feed remains publicly available at 0.5.2 for sites that upgrade later;
future release jobs do not need its deploy key or publish there. Cached legacy
download URLs still receive checksum verification in the new updater.

Transfer/export/import behavior is unchanged from qualified 0.5.1. This release
qualifies the updater migration, not new transfers or hosting compatibility.

## Qualification

On 2026-10-07, the full PHP suite passed on Linux PHP 8.3.35 as an
unprivileged user in the official WordPress image. Updater boundary tests cover
stable version gating, malformed/oversized/error metadata, immutable versioned
checksum lookup, missing/mismatched metadata, altered ZIP removal, cached legacy
URLs and unchanged administrator-controlled automatic-update behavior. All six
release-qualification tests, four update-manifest tests and deterministic ZIP
layout/build checks passed. The macOS PHP 8.5 suite reaches the existing
Linux-only request-protection refusal; Linux is the supported test environment.

A fresh, owned ephemeral WordPress 7.1.2 / PHP 8.3.35 / MariaDB 11.4 installation
ran WordPress's native bulk plugin upgrader from the exact published 0.5.1 ZIP
to the exact staged 0.5.2 package. Only Connect's release HTTP requests were
intercepted with staged bytes for this pre-publication check. In a new PHP
process, the upgraded active plugin discovered and checksum-verified the package
from the source-repository URLs and refused to offer its current version again.
The same scoped connection record (Push off, Pull on), hash/owner, private
storage path and completed private journal were retained. The test's containers,
network and temporary fixture files were removed. This is a native WordPress
integration test with staged transport, not a claim of a production-site update.

`tests/integration/github-update-wordpress.py --published` repeats the transition
and new-source checks over public HTTPS after publication. Stable publication
also requires the PHP 8.1–8.3 and package GitHub CI gate. The exact source and ZIP
are recorded in [`0.5.2.json`](0.5.2.json).
