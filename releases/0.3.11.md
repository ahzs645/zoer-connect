# Zoer Connect 0.3.11 qualification

This release normalizes MySQL/MariaDB integer display widths during source and destination schema comparison. The integer type, nullability, defaults, keys, engine and other schema details remain checked. It also adds WordPress dashboard update discovery from a public, versioned GitHub release feed and verifies each downloaded ZIP against the release manifest SHA-256 before installation. The source repository remains private; the public repository contains qualified distribution ZIPs only.

The schema change was exercised during the 2026-09-23 PGAIR local-to-Hostinger Push. The original plugin rejected `wp_terms.term_group` because the source used `bigint(10)` and the destination used `bigint(20)`. After the equivalent normalization was applied to the destination plugin, the saved import resumed, verified its tables, applied 1,494 selected artifacts including the database, completed, and reopened the site. The live homepage, four inner pages, representative images and the connector connection were checked afterward. That production result qualifies this schema difference; it does not imply that every other SQL schema mismatch is safe.

The PHP suite includes a focused regression test for display-width equivalence and rejection of a changed integer type. Update tests cover a newer qualified version, invalid metadata, plugin isolation, valid ZIP checksum and changed ZIP rejection. The package layout and deterministic build are checked separately. GitHub Actions runs the PHP suite on PHP 8.1, 8.2 and 8.3 before publishing. WordPress dashboard update discovery and installation on the live site are checked after the release is built; 0.3.11 itself is installed once using the release ZIP because older versions have no update-discovery code. Automatic updates remain disabled unless an administrator enables them.
